题不在多，在于**每道题都有骨架**：先说结论、再说判断依据、最后给处理动作。下面 30 题按主题分组，每题一条骨架加一句追问预警。

## 一、Linux 与系统（6 题）

**1. 服务器 CPU 不高但 load 很高，怎么查？**
骨架：`load` 高但 CPU 低 → 多半是 **IO wait 或 D 状态进程** → `top` 看 `%wa`、`ps aux | awk '$8~/D/'`、`iostat -x 1`、`vmstat 1` 看 `b` 列。
追问：D 状态进程杀得掉吗？——杀不掉，要等 IO 返回或重启/摘流。

**2. 磁盘满了，但 `du` 加起来对不上？**
骨架：先 `df -h` 定位挂载点 → `df -i` 排除 inode → **被删除但仍被进程占用的文件**：`lsof | grep deleted`，重启进程或 `> /proc/PID/fd/N` 释放。
追问：日志目录满了怎么临时救急？——清空（`> file`）而不是 `rm`，避免句柄不释放。

**3. 一个服务起不来，你的排查顺序？**
骨架：`systemctl status` → `journalctl -u xxx -n 100` → 端口占用 `ss -lntp` → 配置文件语法 → 依赖（数据库/目录权限/环境变量）→ 手动前台启动看报错。

**4. 权限 644 / 755 / 777 分别什么意思？**
骨架：读 4 写 2 执行 1；三组是属主/属组/其他。755 = 属主 rwx、其他 r-x。生产目录别 777，要按角色授权，必要时用 ACL。
追问：`chmod 4755` 的 4 是什么？——SUID。

**5. 怎么排查一个进程内存持续上涨？**
骨架：`ps`/`top` 定位进程 → `pmap -x PID` 看映射段 → JVM 用 `jmap -histo`/heap dump → 区分是堆内泄漏还是堆外（DirectBuffer/线程栈）→ 结合 GC 日志。
追问：OOM Killer 怎么确认？——`dmesg -T | grep -i "killed process"`。

**6. 定时任务没执行，怎么查？**
骨架：`crontab -l` 确认存在 → 看 `/var/log/cron` 或 `journalctl -u crond` → **环境变量差异**（cron 的 PATH 很短）→ 脚本用绝对路径 → 权限与换行符（CRLF）。

## 二、网络（5 题）

**7. 打开一个网页很慢，怎么定位？**
骨架：分层——DNS（`dig` 耗时）→ TCP 握手（`curl -w` 的 `time_connect`）→ TLS（`time_appconnect`）→ 首字节（`time_starttransfer`）→ 内容下载（`time_total`）；再用 `ping`/`mtr` 看链路丢包。
追问：`curl -w` 怎么写？——`curl -o /dev/null -s -w '%{time_namelookup} %{time_connect} %{time_starttransfer} %{time_total}\n' URL`。

**8. 502 和 504 的区别？**
骨架：502 = 网关收到上游的**无效响应或连不上**（进程挂了/端口错/协议不对）；504 = 网关**等上游超时**（上游太慢）。排查第一步都是看 Nginx `error.log`。

**9. TCP 三次握手四次挥手，为什么是三次/四次？**
骨架：三次为了**双向确认 + 防止历史连接**；四次因为 TCP 全双工，两个方向要各自关闭（FIN 各一次）。TIME_WAIT 等 2MSL 是为了让最后的 ACK 能重传。

**10. 能 ping 通但端口连不上，可能是什么原因？**
骨架：ping 走 ICMP、端口走 TCP，两回事 → 防火墙（`firewall-cmd --list-all`/`iptables -L`）→ 服务只听 127.0.0.1（`ss -lntp` 看绑定地址）→ 安全组/ACL → SELinux。

**11. DNS 解析失败怎么排查？**
骨架：`/etc/resolv.conf` 里的 nameserver 是否可达 → `dig @8.8.8.8 domain` 换服务器验证 → `nslookup` 看是否有记录 → `getent hosts` 走 nsswitch（`/etc/hosts`、`/etc/nsswitch.conf`）→ 缓存（nscd/systemd-resolved）。

## 三、数据库（6 题）

**12. 一条 SQL 很慢，怎么优化？**
骨架：`EXPLAIN` 看 type/key/rows → 是否全表扫、是否回表过多 → 加/改索引（最左前缀、覆盖索引）→ 减少返回列与排序 → 深分页改游标 → 仍慢则看锁等待、连接数、磁盘 IO。

**13. 索引为什么用 B+ 树而不是 B 树/哈希？**
骨架：B+ 树**非叶子只存键、叶子存数据且链表相连** → 同样的页能放更多键、树更矮、范围查询走叶子链表；哈希不支持范围与排序。

**14. 事务隔离级别与幻读？**
骨架：读未提交 / 读已提交 / 可重复读（MySQL 默认）/ 串行化；InnoDB 用 **MVCC + 间隙锁**在 RR 下解决大部分幻读。
追问：RC 和 RR 的区别体现在哪？——快照读的时机、间隙锁是否生效。

**15. 主从延迟怎么发现与缓解？**
骨架：`SHOW SLAVE STATUS` 看 `Seconds_Behind_Master` → 原因：大事务、批量写、从库单线程回放、从库资源不足 → 缓解：拆小事务、并行复制、关键读走主库、监控告警。

**16. 备份策略怎么设计？**
骨架：全量（周）+ 增量/binlog（持续）+ 异地保存 + **定期恢复演练**；RPO/RTO 决定频率。逻辑备份 mysqldump 适合小库与跨版本，物理备份 XtraBackup 适合大库。

**17. 生产上误删了数据怎么办？**
骨架：**先停业务写入 → 别重启别刷盘** → 确认误操作时间点 → 全量备份恢复到临时实例 → binlog 回放到误操作前 → 核对后导回；同时评估影响范围并报备。

## 四、中间件（5 题）

**18. 缓存与数据库怎么保持一致？**
骨架：先更新库再删缓存（+ 延迟双删），或订阅 binlog 异步失效；说明「无法做到强一致，只能缩短不一致窗口」，再补穿透/击穿/雪崩的应对。

**19. Redis 突然变慢怎么查？**
骨架：`SLOWLOG GET` → `--bigkeys` 找大 key → 是否有 `KEYS *`/`FLUSHALL` → 内存是否触顶淘汰 → 持久化 fork 抖动 → 网络与连接数。

**20. 消息队列积压了怎么办？**
骨架：先判断是生产暴涨还是消费变慢 → 加消费者（不超过分区数）→ 优化单条处理 → 毒消息隔离重试 → 削峰限流；说明至少一次投递要求消费端幂等。

**21. Nginx 连接数打满怎么处理？**
骨架：`ss -s` 看连接状态分布 → `worker_connections × worker_processes` → `ulimit -n`/`somaxconn` → 上游长连接复用、客户端超时收紧 → 确认是不是短连接风暴。

**22. 怎么保证接口幂等？**
骨架：唯一索引/去重表、token 机制、状态机（只允许从 A 到 B 一次）、分布式锁；说明幂等键怎么选（业务单号 + 操作类型）。

## 五、容器与交付（4 题）

**23. Docker 容器起来就退出，怎么查？**
骨架：`docker ps -a` 看退出码 → `docker logs` 看应用报错 → `docker inspect` 看 CMD/ENTRYPOINT 与 OOMKilled → 前台进程是否真的常驻（别用 `nohup &` 当主进程）。

**24. Pod 一直 Pending / CrashLoopBackOff 怎么查？**
骨架：`kubectl describe pod` 看 Events → Pending：资源不足/污点/亲和性/PVC 未绑定/镜像过大；CrashLoop：`logs --previous` 看上次崩溃、探针配置是否过严、依赖是否就绪。

**25. 上线切换方案怎么写？**
骨架：切换范围与时间窗口 → 前置检查清单 → 数据备份与迁移步骤 → 切换步骤（可回滚）→ 验证用例 → **回滚预案与决策人** → 通知与值守安排。

**26. 数据迁移怎么保证不出错？**
骨架：字段映射表 → 清洗 → 试迁移记录耗时与失败行 → **三张核对表（条数/金额合计/抽样明细）+ 客户签字** → 正式迁移停写、备份、留痕。

## 六、业务与软素质（4 题）

**27. 客户说系统算的数不对，你怎么处理？**
骨架：先确认口径（金额取哪个、时间按哪个字段、部门按什么归属）→ 用 SQL 复现与核对 → 出差异归类统计 → 给结论（口径问题/数据问题/程序问题）→ 书面反馈。**七成是口径问题。**

**28. 需求做不完但客户催上线，怎么办？**
骨架：拆优先级（必须/应该/可以）→ 明确本期不做范围并让客户书面确认 → 给替代方案（临时手工流程/延后）→ 上报项目经理 → 风险写进上线方案。

**29. 你没有 ERP 经验，为什么觉得能做这个岗？**
骨架：承认边界 → 展示业务主线的结构化准备（差旅报销链路、凭证生成、迁移对账）→ 说明补齐路径（熟悉产品字段与菜单）→ 用一个具体例子证明学习速度。

**30. 你怎么用 AI 工具提升效率？**
骨架：给具体场景——查报错、写 SQL 与脚本、生成测试用例、翻译文档、整理会议纪要；**加一句边界**：涉及客户数据的脱敏、结论必须自己验证。
