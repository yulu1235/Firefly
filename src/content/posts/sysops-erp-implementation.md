投实施岗时最容易被问倒的不是 Linux，而是「你说说报销单从提交到付款都经过谁」。技术能突击，业务逻辑必须提前建好骨架。

## 一、先立主线：一条差旅报销的完整链路

几乎所有商旅费控系统都是这条主线：

```
出差申请（预算预占）
   ↓
订票/酒店（协议价、差标控制）
   ↓
行程结束 → 报销单（关联申请单、贴发票）
   ↓
部门审批 → 财务审核 → （共享中心影像/稽核）
   ↓
生成凭证 → 付款 → 核销预占预算
```

**每个箭头都是一个可能出问题的环节**，也是客户会来问你的地方：

| 环节 | 高频问题 | 你要能答的 |
| --- | --- | --- |
| 出差申请 | 预算不够能不能提？ | 预占规则、审批流条件 |
| 订票 | 超标能不能订？ | 差标（职级 × 城市 × 舱位/房标） |
| 报销 | 没关联申请单能报吗？ | 事后补单规则、跨期处理 |
| 审批 | 为什么我的单子卡住了 | 审批流节点、代理人、转办 |
| 财务审核 | 发票校验不通过 | 发票查验、抬头/税号/重复报销 |
| 凭证 | 借贷方不对、科目错 | 科目映射、辅助核算 |
| 付款 | 报销了没到账 | 付款批次、银企直连、失败原因 |

面试时说得出这条链路和每个环节的一两个坑，比背十条 Linux 命令更能说明你来了能上手。

## 二、三个业务概念必须分清

### 1. 财务共享中心（SSC）

把各分公司重复的核算工作（报销审核、应付、总账）集中到一个中心做，靠**影像 + 工单 + 标准化流程**运转。

实施时要处理的核心问题是 **组织与权限的切分**：哪些业务留在本地财务、哪些进共享池、共享人员按什么范围（公司/费用类型）分工。这类需求变更几乎每次上线都会遇到。

### 2. 业财一体化

业务单据（报销单、采购单）通过**科目映射规则**自动生成会计凭证，而不是财务手工做账。

排查「凭证不对」的标准顺序：

1. 业务单据的**费用类型 / 供应商 / 部门**对不对；
2. **科目映射表**里这个组合有没有维护；
3. **辅助核算**（部门、项目、供应商）是否带全；
4. 凭证模板的**借贷方向与金额取数**字段是否配置正确；
5. 期间是否已结账（跨期要红冲或下期调整）。

### 3. 借贷记账

不用学会计，但要记住两条：

- **有借必有贷，借贷必相等**；
- 费用发生记借方、负债增加记贷方：报销时 `借：管理费用-差旅费 / 贷：其他应付款-员工`，付款时 `借：其他应付款-员工 / 贷：银行存款`。

客户说「凭证不平」，你就去看金额合计数和辅助核算项，这两处占八成。

## 三、实施交付的六个阶段

| 阶段 | 产出物 | 你要花的时间 |
| --- | --- | --- |
| 项目启动 | 范围说明、计划、干系人清单 | 搞清楚谁说了算 |
| 需求调研 | 调研纪要、差异清单（标准功能 vs 定制） | 最多，也最值钱 |
| 配置与开发 | 参数配置、权限、接口联调 | 中等 |
| 测试（SIT/UAT） | 测试用例、缺陷清单、签字确认 | 关键，别省 |
| 上线切换 | 切换方案、数据迁移、回滚预案 | 高风险，预案先行 |
| 运维移交 | 操作手册、培训记录、交接单 | 决定售后成本 |

### 三个最容易翻车的地方

**1. 需求口头承诺。** 客户在饭桌上说「这个应该不难吧」，你点头了，后面就是无偿加班。规矩是：**所有新增需求走变更单，写清工作量与影响**。

**2. UAT 没签字就上线。** 上线后每个人都是产品经理。UAT 的验收清单要客户书面确认，尤其是「哪些功能本期不做」。

**3. 数据迁移没做对账。** 迁移不是「导进去能查就行」，必须给出**迁移前后总数、金额合计、抽样明细**三张比对表，并让客户签字。

## 四、数据迁移的标准动作

```text
1. 盘点源数据 → 字段映射表（源字段 / 目标字段 / 转换规则 / 是否必填）
2. 清洗（去重、补全、统一编码、处理历史脏数据）
3. 试迁移（测试环境，记录耗时与失败行）
4. 核对（条数 / 金额合计 / 关键业务抽样 N 条）
5. 正式迁移（停写、备份、执行、核对、开写）
6. 留痕（脚本、日志、核对报告、时间窗口）
```

对账 SQL 的老套路还是三步：总数、金额合计、明细抽样。前面 MySQL 那篇有模板。

## 五、上线切换的三种方式

| 方式 | 适用 | 风险 |
| --- | --- | --- |
| 一次性切换（Big Bang） | 系统小、用户少 | 高，全押在一个晚上 |
| 并行运行 | 财务类关键系统 | 低，但双份工作量 |
| 分批/分模块切换 | 大集团、多组织 | 中，要做好数据同步 |

不管哪种，**回滚预案必须先写好并演练**：回滚到哪个版本、数据怎么回退、谁拍板。

## 六、和客户打交道的四条经验

1. **先复述再回答。** 「我确认一下，您说的是……对吗」——一句话能省掉一半返工；
2. **给方案不给结论。** 客户问「能不能做」，答「能，需要 X 天，影响 Y」比答「能」有价值；
3. **坏消息早说。** 延期三天今天说，比明天说损失小得多；
4. **留痕。** 会议纪要、变更单、验收单，全部落文字。这不是防人，是防遗忘。

## 七、面试里怎么讲业务

被问「你没有 ERP 经验怎么办」，可以这样答（结构比内容重要）：

> 我确实没有生产环境的 ERP 实施经验，但我把这类系统的通用主线梳理过：报销单从出差申请、预订、报销、审批到凭证付款的链路，以及每个环节常见的配置点（差标、审批流、科目映射、辅助核算）。我也练过用 SQL 做迁移对账的三步核对。上手时我需要的是熟悉贵司这套产品的具体字段和菜单，业务逻辑这一层我可以比较快地接上。

**承认边界 + 展示结构化准备 + 说明补齐路径**，比硬装懂更可信。
