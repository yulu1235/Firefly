## 一、操作系统概述

### 1.1 它到底在干什么

操作系统是**最基本的系统软件**，干三件事：

1. **管理与控制**：管理整个计算机的硬件和软件资源；
2. **组织与调度**：合理组织、调度计算机的工作和资源分配；
3. **提供接口**：给用户和应用程序提供方便易用的接口与环境。

层次上它是夹在中间的一层：**用户 → 应用程序（浏览器/微信/Office）→ 操作系统 → 硬件（CPU/内存/磁盘/I/O 设备）**。向下管资源，向上供接口。

课件用餐厅打比方：厨房和餐桌是硬件，一桌桌客人是应用程序，操作系统是餐厅经理——先给谁做菜是处理机调度，谁坐哪张桌是内存分配，食材放哪个仓库是文件管理。

四大管理功能正好对应后面的章节：

| 模块 | 管什么 | 对应章节 |
| --- | --- | --- |
| 处理机管理 | 进程、线程、调度、同步互斥、死锁 | 第 4–12 章 |
| 存储器管理 | 分页、分段、虚拟内存、页面置换 | 第 13–16 章 |
| 文件管理 | 目录、文件分配、空闲空间管理 | 第 17–18 章 |
| 设备管理 | I/O 控制方式、磁盘调度 | 第 19 章 |

接口分两类：**命令接口**给用户用（联机命令如 `ls -l`，脱机命令如 `.bat`），**程序接口**给应用程序用，也就是**系统调用**（`read()`、`write()`、`fork()`）。两者最终都落到内核。

### 1.2 四大特征

| 特征 | 含义 | 关键区分 |
| --- | --- | --- |
| **并发** | 一段时间内有多个程序在推进 | 单核是交替执行，宏观同时、微观串行；**并行**才是多核同一时刻真正同时 |
| **共享** | 系统资源可被多个并发进程共同使用 | **互斥共享**：打印机、摄像头，一段时间只许一个进程用；**同时共享**：磁盘文件、可重入代码，宏观上可同时访问 |
| **虚拟** | 一个物理实体映射成多个逻辑对应物 | **时分复用**：物理 CPU → 多个逻辑 CPU；**空分复用**：物理内存 + 磁盘 → 虚拟内存 |
| **异步** | 进程以不可预知的速度向前推进 | 走走停停：运行 → 等待 → 运行 → 等待 |

这里最容易被问住的是关系题：**并发和共享是最基本的两个特征，互为存在条件**；没有并发，进程串行执行，就谈不上资源共享；没有共享，并发进程也无法推进。而且**没有并发，就谈不上虚拟和异步**。

### 1.3 发展与三类系统

发展主线：**手工操作 → 单道批处理 → 多道批处理 → 分时 → 实时**。

- **单道批处理**：CPU 算的时候 I/O 闲着，I/O 的时候 CPU 闲着，利用率低。
- **多道批处理**：A 等 I/O 时让 B 上 CPU，CPU 和 I/O 并行，效率上去了，但**人机交互很差**。
- **分时系统**：时间片轮转，多个用户轮流用 CPU，各自感觉自己独占机器，解决了交互问题。
- **实时系统**：必须在截止时间前完成，比如导弹制导、工业控制，追求及时性和可靠性。

| 系统类型 | 追求的目标 | 特点 |
| --- | --- | --- |
| 多道批处理 | 资源利用率、吞吐量 | 无交互 |
| 分时系统 | 交互性、响应时间 | 时间片轮转 |
| 实时系统 | 及时性、可靠性 | 截止时间 |

## 二、运行机制与系统调用

### 2.1 特权指令与 CPU 状态

指令分两类：

- **特权指令**：I/O 指令、关中断/开中断、设置内存保护寄存器、修改程序状态字（PSW）。只允许内核程序执行。
- **非特权指令**：加减乘除、数据传送、跳转、比较等，用户程序也能用。

相应地，CPU 有两种状态：

- **核心态（管态/内核态）**：可以执行全部指令；
- **用户态（目态）**：只能执行非特权指令。

切换方向是必考：

- **用户态 → 核心态**：唯一途径是**中断/异常**，由硬件自动完成切换；
- **核心态 → 用户态**：执行一条修改 PSW 的特权指令，把标志位改回用户态。

### 2.2 中断与异常

| 类别 | 来源 | 典型例子 |
| --- | --- | --- |
| **外中断** | CPU 外部，与当前指令无关 | 时钟中断（时间片用完）、I/O 完成中断 |
| **内中断（异常）· 陷入** | CPU 内部，有意为之 | 系统调用 |
| **内中断（异常）· 故障** | 可能被修复 | 缺页 |
| **内中断（异常）· 终止** | 无法恢复 | 硬件故障 |

记忆点：**外中断是异步的，内中断是同步的**（由当前指令引发）。外中断让操作系统重新拿回 CPU 控制权，是并发和抢占的基础；故障里的「缺页」直接通向后面的虚拟内存和页面置换。

### 2.3 系统调用的四步

1. 把参数传到寄存器；
2. 执行**陷入指令**（访管指令）；
3. 内核处理系统调用；
4. 返回用户态继续执行。

三个高频易错点：

- **陷入指令是在用户态执行的，而且它不是特权指令**；执行后引发内中断，才进入核心态。
- **和资源有关的操作必须经过系统调用**：申请内存、读写文件、创建进程、操作 I/O 设备。
- 系统调用是请求内核服务的唯一方式。

### 2.4 大内核 vs 微内核

| 对比 | 大内核（宏内核） | 微内核 |
| --- | --- | --- |
| 内核里有什么 | 进程管理、内存管理、文件系统、设备驱动 | 只留时钟、中断、原语等最基本功能 |
| 其他服务 | 都在内核态 | 文件服务、内存服务、驱动在用户态 |
| 优点 | 性能高，不用频繁切换状态 | 结构清晰、可靠，一个服务崩了不拖垮内核 |
| 缺点 | 结构混乱、难维护、可靠性低 | 频繁切换、性能低 |
| 代表 | Linux | Minix、QNX |

## 三、进程

### 3.1 程序与进程

- **程序**是静态的，存在磁盘上，是指令集合，像菜谱；
- **进程**是动态的，是程序的一次执行过程，有生有灭，像做菜的过程。

一个程序可以对应多个进程。比如同一个聊天软件开两个账号，就是两个 PID 不同的进程。

进程实体由三部分组成：**PCB + 程序段 + 数据段**。

PCB 里存什么：PID、状态、优先级、寄存器（PC、SP 等）、内存指针、打开的文件……可以把它理解成操作系统给进程建的那份档案。

> **PCB 是进程存在的唯一标志。**
> 创建进程 = 创建 PCB；撤销进程 = 回收 PCB。
> 考试常挖坑：只分配了内存和 CPU、但没建 PCB，这个进程是不存在的。

### 3.2 五种状态与转换

创建态、就绪态、运行态、阻塞态、终止态。

- 创建态 → 就绪态：系统完成初始化，进入就绪队列；
- 就绪态 → 运行态：被调度器选中，分到 CPU；
- 运行态 → 就绪态：时间片用完，或被更高优先级进程抢占；
- 运行态 → 阻塞态：**主动**请求 I/O、等待某个事件；
- 阻塞态 → 就绪态：**被动**等待的事件发生、被唤醒；
- 运行态 → 终止态：正常结束或异常退出。

**不存在的转换**（选择题最爱考）：

1. **阻塞态 → 运行态**：阻塞态必须先回到就绪态，再排队等调度，不能直接抢 CPU；
2. **就绪态 → 阻塞态**：就绪态还没拿到 CPU，没法发起 I/O 请求。

口诀：**主动变阻塞，被动变就绪**。

### 3.3 原语与上下文切换

**原语**是不可中断的操作，进程的创建、终止、阻塞、唤醒、切换都用原语实现。原子性靠「**关中断 → 执行原语各条指令 → 开中断**」保证：关中断期间系统不接受外部中断，这一段就不会被打断。

**进程切换**就是保存与恢复现场：

1. 把当前进程 P1 在 CPU 寄存器里的值（PC、SP、AX 等）保存到 P1 的 PCB；
2. 把下一个进程 P2 的 PCB 里的寄存器值恢复到 CPU 寄存器。

这叫**上下文切换**，**是有开销的**——切换时 CPU 没在执行用户程序，纯粹在做调度管理。进程切换比线程切换贵，因为还要换页表、地址空间等。

## 四、线程与进程通信

### 4.1 为什么要有线程

聊天软件要同时「收消息」「发消息」「刷新界面」。如果用多进程，每个进程有独立地址空间，共享聊天记录很麻烦，得走复杂的 IPC。

线程是进程内部的一个执行流，被称为**轻量级进程**。核心区别只有一句话：

> **进程是资源分配的基本单位，线程是 CPU 调度的基本单位。**

| 维度 | 同一进程内的线程 |
| --- | --- |
| **共享** | 代码段、数据段、打开的文件、堆 |
| **私有** | 程序计数器（PC）、寄存器、栈 |

同一进程内线程切换不引起进程切换，开销小；但也正因为共享太多，一个线程踩内存，整个进程一起崩。

### 4.2 用户级线程、内核级线程与三种模型

| | 用户级线程（ULT） | 内核级线程（KLT） |
| --- | --- | --- |
| 谁管理 | 用户空间的线程库 | 操作系统内核 |
| 内核看得见吗 | 只看得到进程 | 能感知每个线程 |
| 优点 | 切换快，不用进内核 | 一个阻塞其他照跑；支持多核 |
| 缺点 | 一个阻塞 → 整个进程阻塞；无法利用多核 | 切换要进核心态，开销大 |

三种多线程模型：

- **多对一**：多个用户级线程映射到一个内核级线程。内核只看到 1 个，只能在一个核上跑，一个阻塞全部阻塞。
- **一对一**：一个用户级线程对应一个内核级线程。
- **多对多**：多个用户级线程映射到多个内核级线程。

**核心考点：内核级线程才是处理机分配的单位。** 内核级线程只有 1 个，用户级线程开 100 个也没法并行。

### 4.3 进程通信（IPC）

进程地址空间独立，不能直接读对方内存，必须借操作系统提供的机制：

| 方式 | 特点 | 注意 |
| --- | --- | --- |
| **共享存储** | 在内存里开一块共享区，双方直接读写，**速度最快** | 同步互斥要自己保证 |
| **消息传递** | 直接通信 `send(Q,msg)` / `receive(P,msg)`；间接通信过信箱 | 系统负责管理，适合分布式 |
| **管道** | 内存缓冲区，一端写一端读，**FIFO** | 普通管道**半双工**；双向通信要两根管道 |

## 五、处理机调度（上）

### 5.1 三个层次

| 层次 | 别称 | 做什么 | 频率 |
| --- | --- | --- | --- |
| 高级调度 | 作业调度 | 从外存后备作业里挑作业进内存、建 PCB | 最低 |
| 中级调度 | 内存调度 | 挂起/激活，把暂时不能跑的进程换出、把能跑的换入 | 中 |
| 低级调度 | 进程调度 | 从内存就绪队列里挑进程上 CPU | **最高** |

中级调度是为了提高内存利用率和系统吞吐量，引入它之后进程状态可以扩展到七种（多了就绪挂起、阻塞挂起）。

### 5.2 抢占与非抢占

- **非抢占式**：P1 在跑，哪怕 P2 很紧急，也得等 P1 跑完或主动阻塞。简单、开销小，但实时性差。
- **抢占式**：P2 更紧急就暂停 P1，先跑 P2。响应快，但**上下文切换的开销变大**，适合分时/实时系统。

### 5.3 评价指标

三个公式必须背：

```text
周转时间     = 完成时间 − 到达时间
带权周转时间 = 周转时间 ÷ 运行时间   （必定 ≥ 1，越接近 1 越好）
等待时间     = 周转时间 − 运行时间
```

### 5.4 用同一组数据算三种算法

四个进程：

| 进程 | 到达时间 | 运行时间 |
| --- | --- | --- |
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

**FCFS**：P1(0–8) → P2(8–12) → P3(12–21) → P4(21–26)

| 进程 | 完成 | 周转 | 带权 |
| --- | --- | --- | --- |
| P1 | 8 | 8 | 1.00 |
| P2 | 12 | 11 | 2.75 |
| P3 | 21 | 19 | 2.11 |
| P4 | 26 | 23 | 4.60 |

平均周转时间 = (8+11+19+23)/4 = **15.25**。

**SJF（非抢占）**：P1(0–8) → P2(8–12) → P4(12–17) → P3(17–26)

| 进程 | 完成 | 周转 |
| --- | --- | --- |
| P1 | 8 | 8 |
| P2 | 12 | 11 |
| P3 | 26 | 24 |
| P4 | 17 | 14 |

平均周转时间 = (8+11+24+14)/4 = **14.25**。

**SRTN（抢占式 SJF）**：P1(0–1) → P2(1–5) → P4(5–10) → P1(10–17) → P3(17–26)

| 进程 | 完成 | 周转 |
| --- | --- | --- |
| P1 | 17 | 17 |
| P2 | 5 | 4 |
| P3 | 26 | 24 |
| P4 | 10 | 7 |

平均周转时间 = (17+4+24+7)/4 = **13**。

对比：**FCFS 15.25 > SJF 14.25 > SRTN 13**。SJF/SRTN 在「所有进程同时可运行」时平均周转时间最短，但**对长作业不利**，短作业源源不断到来时会长作业**饥饿**。

> 做这种题一定先画甘特图再算，别一上来就硬加。SRTN 每来一个新进程都要重新比较一次「剩余时间」，最容易错。

## 六、处理机调度（下）

### 6.1 高响应比优先 HRRN

```text
响应比 = (等待时间 + 要求服务时间) / 要求服务时间 = 1 + 等待时间 / 要求服务时间
```

非抢占式。短作业分母小，响应比容易高；长作业等得越久分子越大，响应比也会涨，最终总能排上——所以**不会饥饿**，兼顾长短作业。

### 6.2 时间片轮转 RR

就绪进程按到达顺序排队，每次给队首一个时间片；用完没跑完就排到队尾。由时钟中断强制剥夺，属于**抢占式**，专为分时系统设计。

时间片大小是考点：

- **太大**：进程一个时间片内就跑完了，退化成 **FCFS**；
- **太小**：切换太频繁，**系统开销太大**，真正干活的时间变少。

### 6.3 优先级调度

每次选优先级最高的进程。分类：抢占式/非抢占式、静态优先级/动态优先级。

缺点很明确：高优先级进程源源不断到来时，**低优先级进程可能饥饿**。工程上常用「老化」（等待越久优先级越高）来缓解。

### 6.4 多级反馈队列

- 设多个就绪队列，**优先级由高到低**（1 级最高），**时间片由小到大**（1 级最短）；
- 新进程一律进 1 级队列；
- 一个时间片没跑完，就降到下一级队列末尾；
- **只有上级队列为空，才调度下级队列**。

好处是短作业在 1 级队列很快跑完，响应快；长作业逐级下沉，也总有机会。**综合表现最好**，但一直有新进程进高级队列时，底层长作业仍可能饥饿。

### 6.5 饥饿对比与计算三步

| 会饥饿 | 不会饥饿 |
| --- | --- |
| SJF / SRTN、优先级调度、多级反馈队列 | FCFS、HRRN、RR |

原因也简单：会饥饿的算法都有「偏好」——偏短、偏高、偏新，不占优势的进程永远排不上队。

调度计算题按三步走：

1. **画甘特图**：时间轴上标出每个进程的起止时间；
2. **列表格**：完成时间 → 周转时间 → 带权周转时间；
3. **求平均**：最后一列求和除以进程数。

## 七、课件点名的五个大题

课件黄色卡片点名了五类必考大题：**调度算法、PV 操作、银行家算法、页面置换、磁盘调度**。调度算法上面已经拆开讲完，这里补后四个的答题骨架。

### 7.1 PV 操作

- `P(S)`：申请资源，`S = S − 1`；若 `S < 0`，进程阻塞，进等待队列。
- `V(S)`：释放资源，`S = S + 1`；若 `S ≤ 0`，说明还有进程在等，唤醒一个。

初值怎么设：**互斥信号量初值为 1**（一把锁），**同步信号量初值为 0**（先等后通知）。

生产者-消费者是标准模板：互斥锁保护缓冲区，两个同步信号量分别表示「空位数」和「产品数」，P 的顺序不能反，否则可能死锁。

### 7.2 银行家算法

数据结构：`Available`（可用资源）、`Max`（最大需求）、`Allocation`（已分配）、`Need = Max − Allocation`。

安全性检查：

1. 找一个 `Need ≤ Available` 的进程，假设它顺利跑完，把它的 `Allocation` 还给 `Available`；
2. 重复，直到所有进程都能排进这个序列；
3. 排得出来就是**安全状态**，这个序列叫**安全序列**；排不出来就是**不安全状态**。

注意：不安全状态**不一定**立刻死锁，但系统已经失去了「保证不死锁」的把握。银行家算法属于**死锁避免**（动态检查），不是死锁预防。

### 7.3 页面置换

- **OPT**：淘汰未来最长时间不用的页，理论最优，无法实现，用来当基准；
- **FIFO**：淘汰最早进入的页，实现简单，可能出现 **Belady 异常**（加内存反而缺页更多）；
- **LRU**：淘汰最久未使用的页，效果接近 OPT，但需要硬件/栈支持；
- **Clock**：给每页一个访问位，环形扫描，访问位为 1 就清零放过，为 0 就淘汰，是 LRU 的近似。

算缺页率时注意：**首次访问的页也算缺页**，但不算「置换」。

### 7.4 磁盘调度

- **FCFS**：按请求顺序，公平但寻道长；
- **SSTF**：最短寻道时间优先，可能**饥饿**；
- **SCAN**（电梯算法）：一个方向扫到头再折返；
- **C-SCAN**：只在一个方向服务，到头直接回起点，回程不服务，寻道更均匀；
- **LOOK / C-LOOK**：不扫到头，到该方向最后一个请求就折返。

## 八、易错点清单

1. **并发 ≠ 并行**：并发是同一时间间隔内交替，并行是同一时刻同时，并行需要多核。
2. **阻塞态不能直接变运行态**，必须先变就绪；**就绪态也不能直接变阻塞态**。
3. **PCB 是进程存在的唯一标志**，不是程序段，也不是内存。
4. **用户态 → 核心态只能靠中断/异常**；核心态 → 用户态靠修改 PSW 的特权指令。
5. **陷入指令在用户态执行，且不是特权指令**，它只是「触发进内核」的那条指令。
6. 和资源有关的操作（申请内存、读写文件、创建进程、I/O）**必须走系统调用**。
7. **大内核性能高但难维护，微内核可靠但切换多**，别把优缺点记反。
8. **进程是资源分配单位，线程是调度单位**；线程共享代码/数据/文件，私有 PC/寄存器/栈。
9. **内核级线程才是处理机分配的单位**；多对一模型下用户级线程再多也不能并行。
10. **管道是半双工**，双向通信要两根；共享存储最快，但要自己做同步。
11. **时间片太大退化成 FCFS，太小则切换开销大**。
12. **SJF 平均周转最短但会饥饿；HRRN 不会饥饿**；FCFS、RR 也不会。
13. **带权周转时间必定 ≥ 1**，等待时间不包括 I/O 等待。
14. **FIFO 有 Belady 异常，LRU 没有**；OPT 无法实现。
15. **银行家算法是死锁避免，不是死锁预防**；不安全状态不等于已经死锁。
